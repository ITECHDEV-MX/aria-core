# Spec — Skills governance F1.b

## Lockfile contract

`skills/MANIFEST.yaml` MUST:
- Start with the comment header `# Generated by aria-core skills lock`.
- Have top-level fields `schema_version` (string), `generated_at`
  (RFC3339), `skills` (array).
- Each `skills[]` entry MUST have `name`, `version`, `owner`,
  `content_sha256` (64 hex chars), `path` (relative to skills/).
- `skills[]` MUST be sorted alphabetically by `name`.

## CLI contract

`aria-core skills lock [path]`:
- Walks `path`, builds the lockfile, writes atomically (tmp+rename).
- Exits 0 on success, 2 on I/O failure.

`aria-core skills check-drift [path] [--json]`:
- Returns 0 with no entries on a clean tree.
- Returns 1 with drift entries on any added/removed/hash/version
  drift.
- Returns 1 with `ErrLockfileMissing` if `MANIFEST.yaml` is absent.
- Returns 2 on I/O failure.

## CI behavior

The Skills Validate workflow MUST run `check-drift` after `validate
--strict`. If drift is detected, the workflow MUST fail.
